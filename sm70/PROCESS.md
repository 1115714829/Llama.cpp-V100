# PROCESS · 标准流程

## 总图

```
阶段 0 基线（只测不改） ──► 阶段 1 优化循环（每个工作项走一遍） ──► 阶段 2 验收
```

三层测试各司其职（详见 BENCH.md）：

- **日常主回路 = 单卡**：L1 算子级（秒级）+ L2 单卡端到端（IQ1_S，分钟级，含贪心门）。内核内部流程都在这里迭代。
- **外环 L3**（256K、卡 0,1,3,4、≈15 min/臂）：定基线、做里程碑 A/B、最终验收。

## 派发方式

主代理用 `tools/dsh-run.ps1` 以 headless 方式直接驱动 DSH 执行任务包（模型 = DSH 默认模型，权限 `workspace-write`），读回结果文件审核。用户不需要手动操作 DSH。

## 阶段 0：基线（只测不改）

| 步 | 内容 | 谁 | 产出 |
|---|---|---|---|
| S0-01 | 服务器盘点（只读） | 主代理 | `results/S0-01-服务器盘点.md` ✓ |
| S0-02 | 源码对账、冻结 BASE 库、256K prompt 定稿 | 执行者 | 结果文件；主代理审核后 commit + tag `sm70-base0` |
| S0-03 | 单卡基线 + 标准脚本冒烟（IQ1_S、GPU 2，两臂） | 执行者 | 结果文件；主代理据此填 L2 基线 |
| S0-04 | BASE 的 L3（三臂） | 执行者 | 结果文件；主代理据此定 BASE 配置与 L3 噪声带 |

**出口**：STATE.md 填好 REF / BASE、噪声带、门参考、排好序的工作队列。

## 阶段 1：优化循环（工作项 Wn）

1. **立项**（主代理）：写设计卡 `tasks/Wn-0-设计.md`：瓶颈证据（L1 / L3 数据）、1cat 对应做法（文件路径）、我们的方案、预期收益（L1 与 L3 各多少）、env 开关名、判负条件。
2. **实现**（主代理；机械部分可派执行者，任务包点名文件）：新路径 env 门控、默认关 → 本地改 → commit → 上传清单 → `build.sh`。
3. **L1 正确性**（执行者）：`op-perf.py … test`，开 / 关两臂。
4. **L1 性能**（执行者）：`op-perf.py … perf`，开 / 关两臂 × 3 进程。没有收益 ⇒ 回第 1 步改设计，或判负。
5. **L2 单卡端到端**（执行者）：开关打开跑贪心门（与 BASE 参考比，不一致 ⇒ 按 RULES R6.3 处理），再跑开 / 关两臂的单卡负载；比对 `[FAK]` 路由行，确认走的是目标路径。
6. **暂采纳**（主代理）：L1 + L2 通过且收益超出噪声 ⇒ 改成默认开 → 重建 → commit → LEDGER 记「暂采纳」；否则 **否决**（LEDGER 记原因，代码留在 env 门后或回退）。
7. **L3 里程碑**（执行者跑，主代理裁决）：以下任一情况跑一次 L3 A/B（同一二进制开 / 关，A-B-B-A 顺序，每臂 3 rep）：改动涉及多卡 / 调度 / 通信；累计 ≥ 2 项暂采纳；预期 L3 收益 ≥ 噪声带。保住 ⇒ LEDGER 记「确认」、STATE 换新 BASE；没保住 ⇒ 撤销暂采纳。

## 阶段 2：验收

最终构建跑 L3（3 rep）对 REF：TTFT、TPOT 两项与显存包络全部满足 = 交付。

## 必须升级给用户的事

启停 `vllm-1cat`；放宽任何门槛；修改 RULES / BENCH；碰生产路径；执行者两次驳回仍未解决的任务。

## 写任务包的规矩（主代理）

1. 一包一件事，执行者 ≤ 2 小时；命令写死路径和 env，不让执行者推断。
2. 必填：目的 / 依赖 / 输入 / 允许修改的文件 / 步骤 / 判定 / 停止条件 / 产出（模板 `tasks/_TEMPLATE.md`）。
3. 所有「如果……则……」的分支写全；包外情况一律「停手上报」。
