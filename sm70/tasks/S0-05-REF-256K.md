# S0-05 · REF（1cat-vLLM）的 256K 标准测试

| 项 | 内容 |
|---|---|
| 执行者 | DSH |
| 依赖 | S0-03；**用户授权**（主代理把 BOARD 本行从「待授权」改成「待派」即代表已授权） |
| 上机 | 卡 0,1,3,4；启停 `vllm-1cat`（仅本任务授权） |
| 允许修改 | `sm70/results/**`；BOARD 本行状态 |
| 预计 | 40 分钟（vLLM 启动 10–20 分钟 + 负载 ≈ 10 分钟） |

## 目的

在同一台机器、同一组卡、同一负载下实测 1cat-vLLM 标准服务，得到 REF。测完服务必须回到 inactive。

## 步骤（每条命令整条复制到 PowerShell 执行）

1. 确认 BOARD 本行状态是「待派」（不是则停止）。上传脚本并加锁（必须 `LOCK_OK`；它同时确认没有 llama-server 在跑、卡 0,1,3,4 空闲）：
   ```powershell
   powershell -ExecutionPolicy Bypass -File F:\vllm+llama.cpp\sm70\tools\push.ps1
   ssh -o BatchMode=yes root@192.168.50.235 'bash /root/llm/test/sm70/tools/lock.sh S0-05 0,1,3,4'
   ```
2. 记录服务原状态（预期 `inactive active active active`）：
   ```powershell
   ssh -o BatchMode=yes root@192.168.50.235 'systemctl is-active vllm-1cat llmscope new-api 1cat-gpu-init; echo TERM_OK_s005a'
   ```
3. 清页缓存 → 启动 vLLM → 等就绪（`HEALTH_OK`，最多 30 分钟）：
   ```powershell
   ssh -o BatchMode=yes root@192.168.50.235 'sync; echo 3 > /proc/sys/vm/drop_caches; echo TERM_OK_dc'
   ssh -o BatchMode=yes root@192.168.50.235 'systemctl start vllm-1cat; systemctl is-active vllm-1cat; echo TERM_OK_s005b'
   ssh -o BatchMode=yes root@192.168.50.235 'bash /root/llm/test/sm70/tools/wait-health.sh 8000 1800'
   ```
   `HEALTH_TIMEOUT` 时：执行 `ssh -o BatchMode=yes root@192.168.50.235 'journalctl -u vllm-1cat --no-pager -n 40 | cut -c1-300'`，记录原文（**若出现 api-key 字样，结果里只写「已略去」**），直接跳到第 6 步。
4. 读投机配置（脚本已屏蔽密钥），记录全部输出：
   ```powershell
   ssh -o BatchMode=yes root@192.168.50.235 'bash /root/llm/test/sm70/tools/vllm-spec-info.sh'
   ```
5. 跑负载（3 rep）。工具提前超时就重发同一条 `rwait`：
   ```powershell
   ssh -o BatchMode=yes root@192.168.50.235 'bash /root/llm/test/sm70/tools/rjob.sh s005 env TAG=s005 ENGINE=vllm REPS=3 bash /root/llm/test/sm70/tools/bench-256k.sh'
   ssh -o BatchMode=yes root@192.168.50.235 'bash /root/llm/test/sm70/tools/rwait.sh s005 3600 40'
   ```
6. **停 vLLM 并确认恢复**（无论前面成败都必须做）：`vllm-1cat` 为 inactive，其余三项与第 2 步相同，卡 0,1,3,4 显存回到 < 500 MiB：
   ```powershell
   ssh -o BatchMode=yes root@192.168.50.235 'systemctl stop vllm-1cat; systemctl is-active vllm-1cat llmscope new-api 1cat-gpu-init; nvidia-smi --query-gpu=index,memory.used --format=csv,noheader; echo TERM_OK_s005c'
   ```
7. 解锁、快照、复制原始产物：
   ```powershell
   ssh -o BatchMode=yes root@192.168.50.235 'bash /root/llm/test/sm70/tools/unlock.sh S0-05; bash /root/llm/test/sm70/tools/srv-status.sh | head -24'
   New-Item -ItemType Directory -Force F:\vllm+llama.cpp\sm70\results\raw\S0-05 | Out-Null
   scp -o BatchMode=yes -r root@192.168.50.235:/root/llm/test/sm70/runs/s005 F:\vllm+llama.cpp\sm70\results\raw\S0-05\
   ```

## 判定

| 结果 | 条件 |
|---|---|
| 完成 | 3 rep 全部成功；第 6 步服务状态与第 2 步一致（`vllm-1cat` inactive）；卡 0,1,3,4 显存已释放 |
| 部分完成 | 负载有 rep 失败，但第 6 步恢复成功 |
| 停手上报 | `LOCK_REFUSED`；第 6 步后 `vllm-1cat` 不是 inactive 或显存未释放（**立即告诉用户**） |

## 停止时的收尾

一定先做第 6 步，再做第 7 步；结果文件写清停在哪一步；BOARD 本行改「待审」。

## 产出

`sm70/results/S0-05-REF-256K.md`：summary 表原样（含 SPREAD、MEM_PEAK）、`vllm-spec-info.sh` 输出（尤其是草稿长度）、第 2 步与第 6 步的服务状态对照、`prompt_tokens`（应与 S0-04 相近，差异来自聊天模板）。**结果里不得出现 api-key。**
