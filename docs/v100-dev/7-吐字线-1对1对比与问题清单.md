# 吐字线 · 1cat-vLLM 1对1对比与问题清单

> **范围**：只覆盖吐字（解码）线。预填充见 [`6-T1C-预填充交付手册.md`](6-T1C-预填充交付手册.md)（互不混写）。
> **判据**（同口径 256K，AGENTS.md §1.0）：tg ≥ **124.6 t/s**、tpot ≤ **8.0 ms/token**、体感流畅；显存 ≤ 4×V16GB。
> **打法**：逐条问题点（P1..P8）按 ROI 施工，每修一条做同源 A/B（≥2 rep 报离散）+ greedy sha 门值复测；先实现追平，再谈超越。

## 0. 我方底账（256K 实测，2026-09-25；SPEC=1 + ROUND=1 + 预填充引擎 ON；gen=128）

> **R375 口径修正（必读，用户 2026-09-25 复核）**
> 1. **判据只锁两个**：**tpot ≤ 8.0 ms（⇔ tg ≥ 124.6）** 与 **TTFT ≤ 152.5 s（spec-on）**。`ms/轮 ≤ 27.2` 是 `8.0 × AL 3.4` 的**派生值**（vLLM 不报 AL），**不得单独当不及格判据**。
> 2. **tg 单点不可比**：2026-09-25 的 **23 个 256K spec-on rep**（同二进制/同 prompt/同采样）tg **26.1–63.6**（**仅 3 个 > 50**）。**轮成本（~83–106 ms）才是物理量**，报数一律"轮成本 + AL 并列"。
> 3. **预填充按 spec-on 比**（BL1 全时段带 DFlash2）：我方 174.0–177.4 s vs 152.5 s = **1.15x 未达标**，缺口 = 草稿链前向 ~23 s；spec-off 151.7 s 不算达标。
> 4. **构建纪律**：一切实机数据必须来自清单门控构建（AGENTS.md §1.0.2）+ manifest；`LLAMA_SPEC_REJ` 此前**从未进过二进制**（R375）。

| 指标 | 我方 | BL1 标准线 | 缺口 |
|---|---|---|---|
| tg | **29.90 t/s** | 124.6 t/s | **4.17x** |
| tpot（ms/输出 token） | **33.36** | 8.0 | **4.17x** |
| AL（输出/轮） | **2.76**（接受率 26.1% = 81/310；mean len 2.76） | ≈3.4 | 1.25x |
| 每轮墙钟 | **90.2 ms**（= 4237 ms / 47 轮） | ≈27 ms | **3.3x** |
| host 侧（全跑 174.5 s） | **enqueue 90.50 s（52%）** + setin 4.46 + alloc 3.06 + build 0.21；**rebuild 122/164 = 74%** | 图缓存机制（见 §1.7） | **主矛盾** |
| draft 配置 | n_max=7、block=8、n_extract=5、sample_from_anchor；提议 310 / 接受 81 | 同口径 DFlash2 | — |

**缺口分解**：tg 4.17x = **每轮 3.3x** × **AL 1.25x** ⇒ **主攻每轮墙钟（P1/P2），次攻 AL（P8）**。

### 0.1 每轮分账（减法分离，R327 实测；`LLAMA_ROUND_TIMING_SYNC=1` + gen128−gen1）

| 每轮 90.6 ms | 数值 | 归属 |
|---|---|---|
| target `graph_compute`：**host 提交墙** | **20.8 ms** | 图发射/调度/拷贝 |
| target `graph_compute`：**GPU 等待** | **33.0 ms** | target verify 算力 |
| **ctx 之外** | **36.8 ms** | draft 2 调用 + CPU selector + CPU sampler + 槽位/HTTP |
| build / alloc / setin | 0.1 / 1.6 / ≈0 ms | 图缓存复用正常 |

⇒ **解码 = host-bound**（~52-58 host vs ~33-39 GPU）。与 BL1 27.2 ms/轮 对账：**host 段 = BL1 整轮 1.91x**；**GPU 段 = 字节 1.44x**（我方 43 GB/轮 = Q8_0 27 + Q4_K_M 16；BL1 ≈30 GB/轮 = **NVFP4 15 + NVFP4 draft 15**）。
⇒ **追平两刀**：① 砍 host（轮 → ~40 ms，tg → ~85）② 字节/格式（GPU 39 → 27，或 AL↑）⇒ tpot 8.0。红线「参数可等价齐平」= 允许对齐 BL1 的 FP8/NVFP4 形态。⚠️ E14 判例：裸换 Q4_K_M 反而慢 ⇒ 字节刀须配融合/M=1 专用 GEMV（1cat marlin FP4 形态）。

### 0.4 逐算子真值（R334；`test-export-graph-ops` + `test-backend-ops perf`，decode M=1）

| **`result_output`（LM head）** | **1540**（1.32 GB） | 817 | TP4 分片后 0.4 ms/位置 × 16 = **~6.4 ms/轮** ⇒ P4 头寸修正为 ~6 |

⚠️ `GGML_CUDA_OP_TIMING=1` 不可靠（已判）；逐算子分账以本配方为准。

### 0.3 每轮分账（LLAMA_SPEC_TIMING 实测，25K/gen96；R329）

| 段 | ms/轮 | 备注 |
|---|---|---|
| **target compute wall** | ≈55 | host 提交 20.8 + GPU ~34 |
| **draft_decode** | **17.73** | 两次 draft 调用（GPU 下限 ~5.9 = 16 GB 权重 ⇒ host ~12） |
| selector（CPU） | 2.29 | fetch 0.10 + topk 0.71 + gate 0.63 + 余 0.85 |
| walk + spec overhead | 0.68 | |
| **合计** | **≈77.7** | 实测 77.5 ✓ 账闭合 |

**真凶二号（P1 细化）**：meta 后端**每 ubatch ~126 个子图**（`ggml-cuda.cu:5075` 注释可证；calls/ubatch≈126）× **~165 µs host/子图 = 20.8 ms/轮** ⇒ P1 真刀 = **子图合并 + 内容键化**（`ggml_cuda_graph_get_key = cgraph->nodes[0]` 指针作 key，容器重建即换 key ⇒ `old_ne=[0,0] old_data=(nil)` 空白比较、warmup 不稳）。
**P3 现状**：`GGML_SPEC_SELECTOR_INGRAPH=1` 在 load_model 即崩（TP 切分 lm_head ⇒ 图内 selector 无法构建）；且 selector 仅 2.29 ms/轮 ⇒ P3 头寸下调，主刀 = **P-D3（draft 2 调用合一，17.73 ms/轮）+ P1 子图合并**。
**真凶三号（R330/R331）**：`inject timing: sync=10.44 + gather=0.07 + copy=0.49 + submit=2.59 ms/call（layers=5 tok=60）` ⇒ draft KV 注入的 10.44 ms **全在一次 `llama_synchronize(ctx_tgt)`**（`llama-context.cpp:4052`）；5 层 getter 内部同步上提后即 no-op（gather 10.47→0.07，上提本身零收益 = 实证）。机制：`extract_layer_inputs`（`:2288`）的异步 D2H 排在 ubatch 计算之后 ⇒ 等拷贝 = 等整流 ⇒ **真刀 = 设备侧特征路径**（特征随 verify 图产出、注入吃 device 指针；1cat = `DFLASH2_FUSED_GDN_METADATA/VERIFY`）或**增量注入**（每轮 8 token 而非整窗 60）。头寸 ~10.4 ms/轮。
**测量法**：`LLAMA_SPEC_TIMING=1`（每轮四段分账 + `inject timing`）+ `GGML_CUDA_DIRECT_DEBUG=1`（图属性逐字段归因）+ `GGML_CUDA_GRAPH_DEBUG=1`（capture/replay/direct）。

## 3. 问题点清单（逐个解决的施工序）

### P0 ★★★ KV q8_0→f16 每步转换税（R375 立项，**R376 已落地第一刀**）

> **R376 进展（2026-09-25）**：TILE 内核加 q8_0 内核内直读（免 f16 全量镜像）已**采纳**——256K spec-on 轮成本 **83.95 → 78.75 ms（−5.2 ms，−6.2%）**，门值 `bcda0092…` 绿、预填充 TTFT 零回归。E1（零代码路线：Split-D 核 + q8-direct）判负（decode 形状 4–10x 慢）。收益缺口（预期 −12 vs 实测 −5.2）待逐节点计时归因。详见 `BASELINE-LEDGER.md` R376。
- **代码实证**：`fattn.cu:763-780` 对 `TILE`/`MMA_F16` **无条件** `need_f16_K = need_f16_V = true`；Volta 下 q=8 的 verify 必走 TILE（`:666`：`Q->ne[1]×gqa_ratio_eff = 8×2 = 16 ≤ 16`）⇒ `fattn-common.cuh:1026/1054` **每次调用**全量 `to_fp16(K_data, K_f16, ggml_nelements(K))`。
- **量化**：每卡 1 KV 头（R368 实测 `hq=6 hkv=1`）⇒ q8_0 KV ≈ **2.28 GB/卡**、f16 镜像 **4.56 GB/卡**（与 R370「f16 目标 KV 4.3 GB/卡」吻合）⇒ **每步 16 层 ≈ 6.8 GB/卡 ≈ 9 ms @751 GB/s**（与 R373 的 256K 截距 ctx 部分 14.9 ms 同量级）。
- **为什么不是"移植 1cat 核"**：上游**已有**原生 q8_0 直读实现（`fattn.cu:413-459` 的 `FATTN_VEC_CASES_ALL_D(…, Q8_0)`，D=64/128/256 全有实例），只是 Volta 分支仅在 `Q->ne[1]×gqa_ratio_eff ≤ 2` 才选 VEC ⇒ **decode verify 拿不到它**。
- **修法候选**：① 给 TILE 加 Q8_0 K/V 实例（保留 TILE 并行度，工作量中等）② 放宽 VEC 门槛到 q=8（零新核，但 VEC 长 KV 并行度存疑 → 先实测）③ 自带 decode 形状核（对齐 1cat `scalar-attention.cu` 的形态）。
- **验收**：同源 A/B ≥2 rep + 门值 `bcda0092…` + `[FAK]`/`[FAKD]` 诊断确认 `need_f16_K/V=0`。
- **预期**：**−9 ms/轮**（256K；轮 ~90 → ~81）；风险低（纯读路径替换，数值可逐位核；但核内 q8_0 反量化成本须实测，R318 曾测 q4-direct 在 prefill 反而 −3.6%）。

### P1 ★★★ host 图管理税（主矛盾）
- **✅ R332 部分落地（零代码 env）**：`GGML_META_SUBGRAPH_CAPTURE=1`（`ggml-backend-meta.cpp:2826` "capture each (subgraph, device) compute as its own graph and replay it"）⇒ **25K 每轮 77.9→68.1（-12.6%）**、**256K 每轮 90.5→86.8（-4.1%）**、tg 29.9→33.9（+13%）；`FULLGRAPH=1` 单开**有害**（+4.1 ms/轮，draft 快但 target 慢）⇒ 明确关闭。已在 `t1c-run.sh` 默认开启。
- **⚠️ 收益随 GPU 占比稀释**（25K -12.6% vs 256K -4.1%）⇒ 256K 剩余 3.2x 不能靠 host 刀解决 ⇒ **GPU 刀不可免**（字节受 Q8_0 验收纪律封顶 ⇒ 须靠效率 23%→40%+ 与 AL↑）。
- **证据**：`enqueue_us=90.50 s / 174.5 s = 52%`；`rebuild=122/164=74%`；`alloc 3.06 s + setin 4.46 s`。同族账本：R294（target 489 调用 rebuild 468；alloc 198 + setin 73 + enqueue 322 ms/调用）。
- **⚠️ R328 修正（判据更新）**：CUDA 图**未被 MoE 禁用**（`mul_mat_id needs sync=0`；Q8_0 Volta mmid 上限 4，`should_use_mmq` 兜底）；基线 **replay=63%**；`GGML_META_REBUILD_CACHE=1` 仅 76.0 ms/轮 vs 基线 77.5（**-2%，噪声内**）⇒ **P1 头寸降级为 -2~5 ms/轮**（与原计划账一致），主刀让位给 **P3/P4/P-D3（CPU 段 + draft 双调用）**。
- **图诊断法**：`GGML_CUDA_GRAPH_DEBUG=1` ⇒ `[GRAPH] props changed / calls capture replay direct`（子图粒度，meta 后端每 ubatch 多子图）。
- **修法方向**：① 解码轮形状分档（q=2..8）建 **CUDA graph 池**复用；② alloc/setin 一次性固化（静态输入指针 + 固定 buffer）；③ meta 容器跳过 rebuild（= 原 P-D1 立项，`GGML_META_REBUILD_CACHE` 现成）。
- **风险**：图捕获与多流互斥（P3RSK 台账）；须门值 sha 复测。
- **验收门**：同源 A/B 各 2 rep + 门值一致。

### P2 ★★★ 每轮 GPU 串行链（90.2 ms/轮）
- **证据**：4237 ms / 47 轮 = 90.2 ms/轮；BL1 ≈27 ms/轮。短上下文分账（E16）：target 36.86（GPU 28.44 + enqueue 8.40）+ draft 6.13 + selector 5.16 + sampler 2.5 = 50.7 ms/轮；256K 下 target GPU 段随 KV 变长。
- **修法方向**：① verify fastpath 同构（只算候选位 logits + top-1，不全量）；② draft/target 双流重叠；③ P3/P4 去掉 CPU 段。
- **预期**：**-20~40 ms/轮**。
- **风险**：候选位 logits 语义须与全量逐位一致（门值兜底）。

### P3 ★★ selector CPU → GPU fast selector
- **证据**：E16 记账 selector 5.16 ms/轮（CPU + meta host）；1cat = `NVFP4_QWEN38_TP4_M1_FAST_SELECTOR`。权重 `selector_predecessor/successor`（各 35.76 MB）已在 draft 权重内。
- **修法方向**：GPU mat-vec 融合（M=1 形态）直接产出候选序，去掉一次 host 往返。
- **预期**：**-3~6 ms/轮** + 轮结构简化。
- **风险**：低（独立算子）。

### P4 ★★ LM head TOP1 + GPU 采样
- **证据**：1cat `LM_HEAD_TOP1` + `SAMPLER_LIBRARY`；我方全 logits + CPU 采样（短上下文 2.5 ms/轮；vocab 大 ⇒ logits 写读带宽可观）。
- **修法方向**：LM head 内融合 top-k/p/greedy 判定，只回传 token id + logprob（verify 只需 top-1）。
- **预期**：**-2~4 ms/轮**。
- **风险**：采样语义（temp/top-k/top-p/min-p/penalty）须逐位对齐 → 门值。

### P5 ★★ GDN 融合（48 层）
- **证据**：R212 profile `GATED_DELTA_NET` 913 µs/层（单设备 test-backend-ops 口径）；1cat 有 `FUSED_GDN_INPUT_FP16` / `FUSED_HC_FP16` / `SHARED_GATE_FUSION` / `DFLASH2_FUSED_GDN_VERIFY`。
- **修法方向**：融合输入投影 + 门控 + 状态更新（Qwen3.8 GDN 结构），verify 侧同构。
- **预期**：**-5~15 ms/轮**。
- **风险**：状态更新数值语义（门值 + PPL 双关）。

### P6 ★★ MoE GEMV 形态（fused W13/W2 + M1 decode）
- **证据**：1cat `..._MOE_QPN_BATCH_FUSED_W13/W2` + `MOE_QPN_M1_DECODE` + marlin NVFP4/MXFP4 GEMM 核；E14 判决"k-quant 在 Volta 上每字节 GPU 时间更多 ⇒ 字节压缩不是杠杆"⇒ **形态（融合/M=1）才是杠杆**。
- **修法方向**：MMVQ 双专家 W13 合并 + 解码 M=1 专用路径；格式守 Q8_0 红线（不引 NVFP4）。
- **预期**：**-5~10 ms/轮**。
- **风险**：MMVQ 批量上限曾破 sha（R202）⇒ 改动须逐形态门值。

### P7 ★ decode 长注意力（q=2..8 形态）
- **证据**：融合 sm70 d256 在 `q<17` REJECT → stock FA；1cat 有 `sm70_grouped_long/scalar-attention.cu` + `E4M3_LONG_ATTENTION_MANIFEST` + `nvfp4_kv_cache_kernels.cu`。R318：q8-direct = 显存使能件（-2.2 GB f16 镜像）非性能刀。
- **修法方向**：decode 形态专用 KV GEMV 核（q8_0 KV 直读 + GEMV），弃 f16 镜像。
- **预期**：**-2~8 ms/轮** + 显存 -2.2 GB/卡（利于 3 卡达标）。
- **风险**：中（新核）。

### P8 ★ AL 提升（1.25x 缺口）
- **证据**：我方 2.76（26.1%）vs BL1 ≈3.4；R201/R199 草稿块扩展已证伪（AL 6.47↑ 但 ms/轮 51.29→73.13，盈亏平衡 p>26%）。
- **修法方向**：**先落 P2/P3 降低每轮成本**，再重测"一轮两块"（盈亏平衡点会随成本下降而移动）；候选序生成策略（dense order / rerank 同构）。
- **预期**：tg ×1.1-1.25。
- **风险**：n_max/块大小属口径参数（BL1 口径 n-max=7 固定，不动）。

## 5. 施工纪律（与预填充同款）

1. 每修一条：**同源 A/B ≥2 rep 报离散** + **greedy sha 门值复测** + 回写账本（R3xx）+ PLAN-GRAPH。
2. 数值二分方法学沿用：score → num → psum → out 逐层宿主复算（见预填充手册 §4）。
3. 复杂机制先做**单调用级探针**再改刀（REF 系探针可复用）。
4. 环境隔离：自建启动器 `/root/libdir-gb/llama-server`；`/root/llm/llama.cpp`、`/root/llm/systemd` 只读；GPU2 与正式服务卡位重叠 ⇒ 跑前确认正式服务未运行。
