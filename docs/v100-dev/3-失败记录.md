## 3.1 运行时 / 图 / 主机

| ID | 尝试 | 结果 | 死因 |
|---|---|---|---|
| **F-F1** | 指针折印快路径（sched 分配） | 零效果 | split_graph 每次 `ggml_free+init` 重建张量，指针身份必漂 |
| **F-F1v3** | 槽命中跳过 needs_realloc | 仅省 7% | alloc 真身 = meta init 钩子遍历 |
| **F-FixA** | 副本/依赖对象池化 `GGML_SCHED_POOL` | **反向 7.8%** | 身份稳定不充分；池化只加税 |
| **F-F3** | 子图级 CUDA 捕获（v1–v6） | 净值 **0±0.3%** 六连不采用 | dispatch 省下的被回放/簿记抵平；p3 税等 |
| **F-FGC** | meta 整调用单图捕获（曾 B2 采用） | **T8 后关闭更快 2.1%** | 整图回放成串行化税；收益基础被 T8 拿掉 |
| **F-E6 线** | 改 meta 容器索引（五次） | 全 abort | 容器与 arena/`init_tensor` 生命周期耦合（改容器须结构性方案=Fix B） |
| **F-P2P** | `GGML_CUDA_P2P=1` 复测 | 边际 **0%** | 旧 +10.6% 已被 NCCL+后续吃尽 |
| **F-图复用 draft** | 「draft 图 0% 复用是 bug」 | **结构性 0%** | 槽位/embd-token 互斥/n_tokens 三道门（E4）；奖赏不存在 |
| **F-延迟 AR / 设备 AR** | 折叠 AllReduce、device push AR | 不采用 | 值被紧邻消费；设备 AR 更慢且**破数值门** |
| **F-early process** | `GGML_SPEC_EARLY_PROCESS` 调用序 | 零效果 | 拷贝/同步窗重排无净收益 |
| **F-sched pool/retry** | 池化、retry_alloc | 否 | 慢路径结构性必需（早期）/ 池化见 FixA |

## 3.2 内核 / GEMM / 注意力

| ID | 尝试 | 结果 | 死因 |
|---|---|---|---|
| **F-MMA** | W8VOLTA-MMA / 手写 `mma.m8n8k4` 解码 GEMM | 比在位 MMVQ **慢 2–3×**，七轮迭代仍败 | n≤8 matvec 纯访存；mma 暂存+碎片重载纯开销；sm_70 **无 int8 mma** |
| **F-F4'** | 调形六杆：nwarps / rows_per_block / mma / 外链断链 / 预取 / 内链断链 | **六杆全灭** | n=8 内存吞吐 34% vs n=1 的 95.6%；外链寄存器外溢 4.5×；预取 +4.5% 恶化；VDR 链深仅 2 |
| **F-X16** | 照抄 jusko D256 FA 常量 | **-1.19%** | 常量形状相关，不可盲抄 |
| **F-MMQ-push** | Q8_0 ne11=8 强推 MMQ | **-31%** | 必须走 MMVQ |
| **F-VDR8** | MMVQ VDR 2→8 | **-17%** | 寄存器压力 |
| **F-LOWBIT** | Q4_K_M 当吐字加速 | **更慢**（58.6 vs 55.8 ms/轮）且 AL 掉 | **E14**：k-quant 在 Volta 上每字节 GPU 时间更多；权重字节不是约束 |
| **F-HMMA 权重** | 量化权重走 FP16 张量核「换格式」 | 口径作废/无端到端 | 预填充本就走 cuBLAS 反量化 F16；DEQ 融合 ABBA **零效果** |
| **F-KV 压缩** | turbo2/3、planar4、iso4 等 | 全负 **-6%～-22%** | V100 路径更慢且伤 PPL |
| **F-KV 反量化当墙** | 「整条 KV 每 ubatch 反量化是预填充主因」 | **证伪** | f16 KV 131K **慢 31%**；墙在 FA 本体扫 KV |

## 3.3 并行 / 部署结构（结论性失败）

| ID | 尝试 | 结果 | 死因 |
|---|---|---|---|
| **F-TP 加速** | TP4 / TP6 吐字 | **+3.6% / +28.6% 变差** | 提交/AR 税 + FP 求和序改变接受率 |
| **F-TP2** | 双卡装 Q8_0 | OOM/断言 | 权重/卡超 16 GB |
| **F-TP6 几何** | 6 卡切 4 KV 头 | 结构性不可用 | 无法整除 |
| **F-draft-device** | `--spec-draft-device` 单卡 draft | 启动 abort | lm_head 在 Meta() 缓冲，单卡 draft 无法执行 |
| **F-layer-split** | layer 切分 | 慢约 40% | 不适合本负载 |

> 加卡**买容量不买速度**——这是部署结论，不是待突破项。

## 3.4 方法论事故（防止再犯）

| 教训 | 说明 |
|---|---|
| 调参 ≠ 开发 | `-ub` 等曾混入「预填充收益」——**已剥离**；两边固定即可 |
| 机制未生效的 A/B | F1 假零效果 ⇒ **必须机制自证计数** |
| env 判存在不判值 | `GGML_META_FULLGRAPH=0` 也是开 |
| 影子源假还原 | 还原须树+影子源双通道 + 标记串三查 |
| `--ctx-size` 不填 KV | 曾得出假「零斜率」 |
| `llama-bench -r 1` 瞬态 | 均值偏低 20–27%，入账须 `-r≥8` |
| 并发测量 / 换库杀进程 | 测量必须独占；构建与测量互斥 |
| 把用户配置写进采用链 | **本次文档重梳的直接原因** |
