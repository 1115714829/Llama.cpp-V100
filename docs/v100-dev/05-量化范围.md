# 量化范围建议（V100 研究）

## 结论（建议）

**主攻本机目标格式 Q8_0（权重）+ q8_0（KV）；其余量化只保证「不回退」，不铺开做全格式优化矩阵。**

不要一上来「q8_0 / q4_k_m / q2_k / … 全都要支持优化」。

## 为什么只主攻 Q8_0

1. **V100 上低比特不是加速项**：E14 同源 A/B，Q4_K_M 轮时 **58.6 ms** vs Q8_0 **55.8 ms**，AL 还更低 ⇒ k-quant 每字节 GPU 时间更多。优化 Q4 **不能**帮你到 tg≥150。
2. **硬指标绑在 Q8_0 + DFlash2** 上（采用链 B0–B5、门值、AL 都是这套）。换格式 = 换一套门值与结论，研究会被摊薄。
3. **真正值钱的二次开发多半与格式无关**：多槽 gallocr、meta、selector、FA 工作分解——这些做完，换格式也吃得到。格式专属内核（MMVQ/MMQ 细调）才是按格式分裂的。
4. **C5 已覆盖 k-quant 交叉点**（V100 mmvq↔mmq = 4，Q4 小批 +15%）⇒ Q4 路径**有基本盘，不必当主线再堆人**。

## 分层（建议写进项目边界）

| 层 | 格式 | 策略 |
|---|---|---|
| **T1 主攻** | **Q8_0 权重 + q8_0 KV**（及 FA/内核对它们的特化） | 全力优化；门值、采用链只认这套 |
| **T2 不回退** | Q4_K_M / Q5_K 等常见 k-quant | 保持 C5 与现有 MMQ 路径可用；**不做**新的格式专属战役 |
| **T3 不做** | Q2_K、IQ 系、奇异格式、为每种量化单独立项 | 除非以后有明确产品需求再开 |

F16/BF16 权重：仅作对照与 cuBLAS 路径需要时使用，不是交付目标。

## 什么时候才值得做「全量化」

同时满足再开：

1. 产品明确要多格式生产，且有人付维护成本；
2. V100 上某种格式**实测快过 Q8_0**（目前 Q4 相反）；
3. 或显存硬到只能上更低位宽——那时是**买容量**，要单独算 decode 代价（E14 已表明会变慢）。

## 与三问的对应

- 吐字 / 预填充 / 显存的**主攻内核与运行时**，对象就是 Q8_0。
- 显存若被迫换 Q4：那是配置/模型选择，**不是**「已突破」；要进账必须重新同源 A/B。
