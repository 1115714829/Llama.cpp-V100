## 1.3 预填充（prefill）/ 256K —— 主场景（R289 起为本次主攻方向）

**墙的口径（R289 重过滤定标，引用只认这里）**：

- 墙 = 长 KV `FLASH_ATTN_EXT`。**78.4% 是峰值 ubatch 算子表占比**（R264）；**全程占比：32K ≈ 19%、256K ≈ 60–66%**（R272 e2e 反解 / RESEARCH 拟合）。
- 效率真基线（R269 口径，FLOPs ×24 头）：stock MMA_F16 **35.8**、Path A **45.9 TFLOPS**。旧说法「仅 1.49 TFLOPS = 峰值 1.2%」**已作废，禁止引用**。
- 1cat 同族梯子：17.92 → **46.63–47.1（v1.3.0 Split-D/N32 = 我们 Path A 的移植源）** → **≈60.8（PR#286/79T）**，79 为实验上限。
- ⇒ 真实差距 = **内核台阶 45.9→60.8（1.33x）× 执行栈/每 ubatch 固定成本残差（约 2x，R291 强化此归因）**；GEMM 与 KV 反量化不是墙。~~TP3 KV 头失衡 1.33–1.5x~~（**R291 已证伪其吞吐杠杆**，算术真实但被非缩放成本遮蔽）。

## 1.5 判据（计划项验收）

1. 同源 A/B，唯一变量是**代码/env 门控**（不是 `-ub`）。
2. **tg 与 ms/轮并列**；≥2 臂报离散；greedy sha256 门。
3. 机制自证计数（特性必须先证明「改的那条路真的走了」）。
4. 比 B5 差的一律不采用（写入失败记录）。
5. 大改 / 新模式：**先停下问用户**。
